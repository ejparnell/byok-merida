# Expose the durable Analysis Run through the dashboard API

The dashboard starts work with `POST /api/v1/applications/analysis/run`, sending the canonical `target` field and a client-generated `Idempotency-Key`; a new run returns `202` with its durable snapshot, an identical key returns the same run, and a distinct start while work is active returns `409` with the active run identity. `GET /api/v1/applications/analysis/runs/active` reconnects a reloaded dashboard, `GET /api/v1/applications/analysis/runs/{runId}` reports progress and outcome, and `POST /api/v1/applications/analysis/runs/{runId}/cancel` requests bounded cancellation. Active progress leads with completions against target, evaluated candidates against Attempt Budget, and Committed Spend against the $0.50 ceiling; expanded detail separates verified provider cost, active reservations, indeterminate reservations, and remaining authorized budget so estimates are never presented as settled charges. The former `limit` request field is replaced rather than retained as a second name for Analysis Batch Target.
