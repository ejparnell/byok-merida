# Bound Application Analysis output

Application Analysis returns exactly three summary sentences and an Analysis Signal Set of at most ten concrete, evidence-backed signals, prioritized by required, preferred, then other useful signals with near-duplicates merged. Each provider call explicitly enables thinking at high effort and allows at most 8,000 generated tokens shared by reasoning and final JSON; recovery never disables thinking or silently lowers effort. Calls remain non-streaming, with a 10-second connection timeout, a 120-second read-inactivity timeout, and a five-minute absolute deadline that provider keep-alives cannot extend. The adapter captures finish reason, model identity, request identity, and usage for settlement but never persists, logs, or exposes reasoning content; a deadline after transmission is indeterminate. Validation treats the summary as one unit but validates signals independently: unsupported, generic, and duplicate signals are discarded before scoring or persistence, and the proposal is accepted when its summary is valid and at least three valid signals remain. Otherwise it may consume another call from the Application Call Budget. Candidate-specific input or output defects become Candidate-Scoped Failures after that budget and allow backfill; transient transport, rate-limit, and provider-server errors may use remaining call slots but become a Run-Scoped Failure when exhausted, while authentication, balance, model, pricing, and spend-authority defects stop immediately instead of being repeated across candidates. This bounded response contract leaves room for visible JSON inside the Analysis Generation Envelope; Match Score describes fit against the prioritized set rather than every phrase in the posting. Resume Creation still reads the complete Job Content independently, so the bounded set does not become an exhaustive downstream requirements contract.
