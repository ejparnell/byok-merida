# Cap each Analysis Run at fifty cents

Every operator-initiated Analysis Run has a hard provider-spend ceiling of $0.50 USD, independent of its Analysis Batch Target. Initial model calls, repairs, retries, and failed or truncated calls all consume this ceiling; controlling spend separately from the Attempt Budget prevents backfill and recovery behavior from creating unbounded cost. Merida's backend is the Spend Enforcement Authority: using the transactional Analysis Run store, it serializes call admission, durably reserves each call's entire worst-case charge before dispatch, and sends the call only when that reservation fits within the remaining ceiling. Provider or gateway budgets, output limits, and price filters are applied where available as defense in depth, but Analysis does not block merely because an external service lacks a no-overshoot dollar control.

Cost Authorization calculates the worst-case reservation using an Input Cost Bound and the maximum reasoning-inclusive output at an approved cache-miss rate. The Input Cost Bound is calculated from the exact rendered request as the greater of the pinned model-tokenizer count plus verified chat overhead or the complete UTF-8 request byte count plus that overhead; character-ratio estimates are not authoritative, and Job Content is never silently truncated or summarized to obtain authorization. Application Analysis is restricted to exact provider endpoint and model combinations in a reviewed local rate card; each entry records its source, rates, verification date, and a validity window ending 30 days after verification, and runtime page scraping is not a pricing authority. Authorization always assumes cache-miss input pricing, and missing or expired approval blocks readiness.

Cost Settlement releases unused reservation only after a proven pre-transmission failure or a valid provider or gateway receipt establishes actual cost; missing or unreconcilable usage leaves the full reservation consumed. When a sent call has no reconcilable outcome, its full reservation is treated as consumed; a fresh retry needs its own authorization and is never treated as free. Monetary values use integer USD micros rather than floating-point dollars. Unknown models, unverifiable rates, an unavailable transactional reservation store, or insufficient remaining spend fail closed without making the call. Completed Applications remain committed, and the run reports a valid partial, spend-limited outcome rather than rolling work back or silently reducing analysis quality.
