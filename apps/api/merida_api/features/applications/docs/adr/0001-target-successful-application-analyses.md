# Target successful Application Analyses

An Analysis Batch Target represents Application Analysis completions rather than attempted Applications. Both newly analyzed Applications and repaired Applications count because each leaves the Analysis Queue complete; failed and skipped Applications do not. A run may advance past failed or skipped Applications to satisfy the target, matching the operator's intent. At creation it captures a canonically ordered Run Candidate Set of eligible Application IDs containing at most twice the target, bounded by the available queue; candidates are reloaded and revalidated before use, but later queue mutations do not alter the set. Evaluating a candidate consumes its slot even when revalidation skips it, and each Application may be evaluated at most once per run so provider work remains finite. Within one Application attempt, the initial call, transport retries, and structured-output repairs share a three-call Application Call Budget rather than multiplying independent retry loops.
