# Own recoverable Resume artifacts by Artifact Set identity

Durable Resume Runs cross Notion Resume and Note pages plus backend-owned PDF storage, where a lost response can make any individual effect ambiguous. The Resumes context will therefore allocate one opaque Resume Artifact Set ID per candidate before artifact work, write that exact identity to both Notion pages and PDF evidence, and treat the final Resume-to-Application relation as the commit marker only after full readback. Recovery reconciles uniquely owned effects forward from a recovery-scoped private checkpoint; it never infers ownership from similarity, regenerates provider output after an artifact effect, or adopts independent work. Interruption and cancellation alone preserve forward recovery. Once a definitive condition makes completion impossible, Merida compensates only exact owned effects through verified reverse barriers; unprovable ownership, effect, or cleanup creates durable Application-scoped quarantine instead.

## Consequences

- Durable Resume Runs require a Notion schema and API migration to exact `Merida Artifact ID` lookup plus single-request enhanced-Markdown page creation and readback.
- Resumes-owned coordination must retain private validated Resume and Note documents while same-run recovery or verified compensation remains possible, even though public run and spend metadata stay content-free.
- PDF storage and compact terminal evidence are addressed by Artifact Set identity rather than human filenames or only a Resume page ID; presentation names remain separate from ownership.
